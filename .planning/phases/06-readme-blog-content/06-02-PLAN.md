```go
package metrics

import (
    "github.com/prometheus/client_golang/prometheus"
    "github.com/prometheus/client_golang/prometheus/promhttp"
)

var Reg *prometheus.Registry
var MessageWireBytes prometheus.Histogram

func init() {
    Reg = prometheus.NewRegistry()
    MessageWireBytes = prometheus.NewHistogram(prometheus.HistogramOpts{
        Name:    "ratchet_message_wire_bytes",
        Help:    "Wire size of serialized ratchet messages in bytes.",
        Buckets: prometheus.DefBuckets,
    })
    Reg.MustRegister(MessageWireBytes)
    // HandshakeDurationSeconds, EncryptDurationSeconds, DecryptDurationSeconds follow same pattern
}
```

Note: Protocol (classical/pq) and role (alice/bob) labels are NOT emitted by the binaries. They are attached at Prometheus scrape time via `static_configs.labels` in `prometheus/prometheus.yml` — keeps binaries label-agnostic.

**Section 8 — Takeaway / conclusion**
The engineering insight: crypto agility is achievable. The application code (Encrypt/Decrypt callers) is identical between classical and PQ. The 10x wire overhead is real and measurable, but it does not leak into your application logic. Go's stdlib `crypto/mlkem` makes this hermetic — no CGo, no external KEM library. When NIST finalizes PQ standards and clients demand it, swapping out the ratchet layer is a small change.
